Remote scanning är lokal scanning över SSH

Appen skannar inte processer själv på remote host. Den hämtar först rå tmux-inventering via SSH, och enrichar sedan panes med `agents ls --json --no-interactive --tmux` som körs på samma remote host mot samma tmux-server.

Host runtime är truth tmux äger sessions, windows, panes, cwd och pane-id. Appen visar och koordinerar.
CLI är metadata-provider `agents` klassar agentprocesser, hook-state, modell, branch och status.
Remote CLI är pinnad App-managed install matchar manifestets `gitCommit` mot appens expected commit.
Viktig gräns Remote hosten behandlas som en egen lokal maskin: appen transporterar kommandon med SSH, men `tmux`, `ps`, `git`, hook-state och `~/.agents/...` läses på remote-sidan.

Från app-refresh till agent metadata

Ett inventory-refresh är två separata steg. Steg ett ger pane-inventering från tmux. Steg två enrichar de pane-id:n som faktiskt finns i inventariet med agentmetadata från CLI:t. 


          

        

      


      

        

          
Install och uppdatering

          
Två vägar in, samma slutläge

          
    
            
  • 
              Bootstrap-scriptet är operator/app-onboarding: det planerar `tmux`,
              Node/npm, git, CLI, helper tools och en default tmux-session. Dry-run är default.
            
    • 
            
  • 
              App-managed ensure körs innan remote metadata-fetch när ingen explicit
              `agentsInstallPath` är konfigurerad. Den är idempotent och exit:ar direkt om manifestet matchar.
            
    • 
            
  • 
              Hook-setup hålls separat: CLI:t kör `autoSetupIfNeeded()` vid start och spawnear
              `agents setup --quiet` i bakgrunden om hook-definitionernas hash har ändrats.

Watchers

          
Scanning är pull, refresh-triggers är push-ish

          

            Själva inventariet hämtas via `tmux list-panes` och `agents ls`. Watchers gör inte en full
            scan själva. De tailar eventfiler och skickar "refresh requested" eller agent runtime events
            tillbaka till appens state machine.
          

          

        

        

          

          

          

        

      


      

        

          
Felmoder

          
Vad händer när något saknas?

          
    
            
  • Remote host timeout: host-fetchen får en failure-rad, men andra hosts kan fortfarande ge partial inventory.
    • 
            
  • `tmux` saknas: integration-promptern markerar `blocked:tmux-missing`; bootstrap behövs eftersom appens integration inte installerar paket.
    • 
            
  • CLI saknas eller är fel commit: app-managed ensure installerar/uppdaterar om ingen explicit preferred path är satt.
    • 
            
  • Hook-state saknas: processdetektion hittar fortfarande agentprocessen, men hook-auktoritativa agenter faller konservativt mot idle tills hooks rapporterar.
    • 
            
  • Metadata missar pane-id: appen enrichar bara pane-id:n från tmux-inventariet och ignorerar okända CLI-payloads.
    •
